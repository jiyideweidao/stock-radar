# 桌面启动器说明

把这个文件夹当成「程序入口」。桌面（`Desktop`）上已经有快捷方式 **股民舆情工作站**，
双击即可——它会先在后台把服务拉起来，再用一个**独立应用窗口**打开工作站（不是浏览器标签页）。

| 文件 | 作用 |
| --- | --- |
| `启动工作站.cmd` | 双击启动：后台拉起服务 + 打开工作站窗口（已开着则直接还原到最前，不重复开窗） |
| `自检工作站.cmd` | 一键自检：本机 + 接口 + 外部数据源逐项打勾，报告写入项目根目录 `selfcheck-report.txt` |
| `停止工作站.cmd` | 停止后台服务（只结束占用 8787 端口的 node 进程，不动其它 node 程序）。**关掉工作站窗口本来就会自动停服务**，这个入口留给「窗口已经不在、或窗口卡住不动」时用 |
| `允许手机访问.cmd` | 双击即用（会自动弹 UAC 提权）：给 Windows 防火墙放行 TCP 8787 入站，让手机能连上本机服务 |
| `start-station.ps1` | 启动逻辑：健康检查 → 必要时拉起 `node server/index.js` → 聚焦已有窗口或打开应用窗口（`-ServerOnly` 只保证服务在跑） |
| `check-station.ps1` | 自检逻辑（`-Fast` 只查本机） |
| `stop-station.ps1` | 停止逻辑 |
| `window-agent.ps1` | 原生窗口代理：常驻进程，从 stdin 读白名单指令，调 user32 操作工作站窗口 |
| `允许手机访问.ps1` | 防火墙规则的实际执行者：`New-NetFirewallRule` 失败时退回 `netsh`；**幂等**，重复跑不会叠加规则；加 `-Remove` 撤销 |
| `setup-shortcut.ps1` | 重新生成图标 + 重建桌面三个快捷方式（启动 / 自检 / 停止；项目换目录后跑一次） |
| `make-icon.ps1` | 用 System.Drawing 现画 `station.ico`，不依赖外部素材 |
| `station.ico` | 桌面图标 |
| `server.log` / `server.err.log` | 后台服务（node）的标准输出与错误输出 |
| `desktop-launch.log` / `desktop-launch.err.log` | 自检脚本拉起后台服务时，启动器的输出与错误 |
| `last-error.txt` | 启动失败时写下的原因（带时间戳）；启动器不再弹对话框 |

## 让手机连上（允许手机访问）

服务本身已经监听 `0.0.0.0:8787`，同一 Wi-Fi 下的手机直接访问 `http://<电脑局域网IP>:8787/?app=1` 就能打开。
打不开的原因**几乎总是 Windows 防火墙拦了入站**，所以准备了这个脚本：

```powershell
desktop\允许手机访问.cmd          # 推荐：双击，自动弹 UAC 提权
desktop\允许手机访问.ps1 -Remove  # 撤销规则（恢复原状）
```

- 只放行 **TCP 8787**，且只对 **专用 / 域** 网络生效（公用网络不放行，避免在咖啡厅 Wi-Fi 上裸奔）。
- **幂等**：已经有同名规则就直接复用，重复执行不会堆出一串冗余规则。
- 脚本结束时调一次 `/api/net`，把手机该访问的地址（和二维码所在菜单位置）打印出来。
- 手机端更完整的说明（PWA 安装、为什么不做 APK）见项目根目录 `README.md` 的「手机访问」章节。
### 不在同一个局域网：Tailscale

`允许手机访问` 管的是「同一个 Wi-Fi」。要让手机在 4G / 别家 Wi-Fi 下也能连，装了 Tailscale 之后
还会额外存在一条**按网卡放行**的规则：

```
stock-radar phone access (Tailscale)   TCP 8787 入站，Profile=Any，InterfaceAlias=Tailscale
```

按网卡限定，所以它**不会**顺带把 Wi-Fi / 网线上的 8787 打开给公网。
另外 Windows 一般会把 Tailscale 网卡判为 `Private` 网络，所以 `允许手机访问.ps1` 那条规则本来也能覆盖它。

## 窗口操作（你要求的视口 / 菜单 / 最大化 / 最小化 / 关闭）

- 窗口用 Edge 的「应用模式」打开（URL 带 `?app=1`），因此标题栏自带 **最小化 / 最大化 / 关闭**，边缘可拖动缩放。
- **页面里也有窗口按钮**：顶栏右侧的 `置顶 / ─ / □ / ✕`，以及菜单栏的「窗口」菜单（最小化、最大化/还原、还原并置于最前、置顶、取消置顶、检查窗口状态、关闭）。
  这些按钮不是装饰——它们走 `POST /api/window/<动作>`，由 Node 转给常驻的 PowerShell 代理，真正操作这个窗口（只接受 9 条白名单指令）。
- 页面底部是**状态栏**：服务状态、当前页签、自检结果徽标（点击看详情）、窗口模式、实时时钟。
- 页面顶部菜单：**页面 / 数据源 / 视图 / 窗口 / 帮助**，右侧显示服务与缓存状态。
- **关窗即关程序**：关闭工作站窗口（标题栏 ✕ / 页面里的「关闭窗口」/ 菜单栏「窗口 → 关闭窗口」/ `Alt+F4`）后，
  后台服务会在几秒内一起退出，不留后台进程。只想收进任务栏、下次秒开，请点「**最小化**」而不是关闭。
  窗口已经不在、或卡住不动时，仍可用 `停止工作站.cmd` 收尾。
- 日志：项目根目录的 `server.log`、`server.err.log`；服务默认监听 `http://127.0.0.1:8787`。

## 窗口按钮点了没反应？

先跑 `自检工作站.cmd` 看「窗口与程序外壳」两组：

| 现象 | 处理 |
| --- | --- |
| 提示「没有找到工作站窗口」 | 当前是用浏览器标签页打开的。用桌面快捷方式启动后才有可操作的窗口 |
| 快捷方式双击没反应 | 右键快捷方式 → 属性 → 确认「目标」指向本文件夹的 `启动工作站.cmd` |
| 找不到 node.exe | 先装 Node.js（https://nodejs.org）再重试。启动器会把原因写进 `desktop/last-error.txt`，并开一个可见窗口显示错误 |
| 服务没起来 | 启动器最多等 60 秒。依次看 `server.err.log`、`desktop-launch.err.log`、`desktop/last-error.txt`。常见是 8787 被别的程序占用 |
| 提示端口被其它程序占用 | 按提示关掉那个程序，或临时换端口：`start-station.ps1 -Server 8899` |
| 关了窗口之后服务也没了 | 这是**设计如此**（关窗即关程序，不留后台进程）。再双击一次桌面快捷方式即可，服务会重新拉起来 |
| 只想关掉界面、不想停服务 | 点标题栏的「─」（最小化）或页面顶栏的「最小化」，不要点「✕」（关闭） |
| 想换窗口大小 | 直接拖边缘；或改 `start-station.ps1` 里的 `--window-size=1560,1020` |

## 两条必须遵守的规则（踩过坑）

1. **绝不能在这个文件夹里用「隐藏窗口 + 对话框」。** 启动器是被隐藏窗口拉起来的，
   弹出的对话框没人能点，会把启动过程永久卡死，用户看到的就只是「双击了没反应、什么都没有」。
   启动失败时改为：写 `last-error.txt`，再另开一个可见窗口把错误显示出来。
2. **目录名带空格是允许的**（本项目就放在带空格的 `New project` 目录下），但拼命令行时必须自己给路径加引号。
   用 `-ArgumentList` 数组把 `-File` 和路径分开传时，PowerShell 不会自动加引号，
   路径会在空格处被截断，报「-File 参数失败 … 路径中包含未转义的空白字符」，服务永远起不来。
   本文件夹里所有走 `Start-Process` 的地方，都已改成先拼一整条带引号的命令行，再用单个字符串传进去。

另外：**不要用管道接住 `start-station.ps1`**，管道句柄会被它的孙进程（Edge）继承，调用方会一直等不到 EOF 而假死。
`check-station.ps1` 已改为「独立进程 + 输出重定向到文件 + 轮询健康检查」。
